Minimum spanning trees

The cheapest way to keep a graph connected, and two classic algorithms that find it with completely different strategies but always agree.

The problem

You have an undirected, connected graph whose edges have weights: the cost of laying a cable, building a road, or running a pipe between two places. You want to keep the graph connected while paying as little as possible in total.

The answer is always a tree. Any cycle has an edge you could drop and stay connected, which would only save money. So you're looking for a spanning tree (one that touches every vertex) with the smallest total weight: a minimum spanning tree, or MST.

This picks up where Which edges can you remove? left off. There, every spanning tree turned out to be the bridges, which are forced, plus some edges chosen from the cycles. The weights decide which cycle edges to keep. Bridges are kept no matter how heavy they are, like H–I (weight 14) below.

The one idea behind both algorithms: the cut property

A cut splits the vertices into two groups. Any edge with one end in each group crosses the cut.

Cut property: for any cut, the lightest edge crossing it belongs to a minimum spanning tree. (If all weights are distinct, it belongs to the MST, which is then unique.)

Why: a spanning tree has to cross every cut at least once, or the two groups wouldn't be connected. Suppose a tree crosses this cut with some heavier edge instead. Swap it for the lightest crossing edge: the result is still a spanning tree, and it's cheaper. The flip side is the cycle property: the heaviest edge on any cycle is never needed.

Kruskal and Prim

Both algorithms build the MST one edge at a time, and every edge they add is the lightest edge across some cut. They just pick their cuts differently:

  • Kruskal's algorithm thinks globally. Sort all edges from lightest to heaviest, then take each edge unless it would close a cycle. Checking for a cycle is exactly what union find is for: an edge closes a cycle when its endpoints already have the same root. Each accepted edge is the lightest edge leaving its endpoint's current group, which is a cut.
  • Prim's algorithm grows a single tree. Start from any vertex, and repeatedly add the cheapest edge that leaves the tree. The cut is always "the tree so far vs. everything else."

Step through either one below. The example has distinct weights, so its MST is unique, and both algorithms must end up with the same tree. Check the total at the end.

    What Kruskal's rejections tell you
    
    
    Every edge Kruskal rejects has endpoints that are already connected by lighter edges, so it's the heaviest edge on a cycle. That makes the rejected edges exactly a maximum set you can remove all at once (from the bridges explainer): E − (V − 1) of them, here 14 − 8 = 6. It's just the cheapest-to-keep version. And no bridge is ever rejected, because a bridge's endpoints can't already be connected some other way.

    Things worth knowing
    
    
      
      
    • Ties. With repeated weights there can be several MSTs, all with the same total weight. Both algorithms still find one of them.
      • 
      
    • Negative weights are fine. Only the order of the weights matters, never their actual values. Adding a constant to every weight doesn't change the MST.
      • 
      
    • It's not a shortest-path tree. The MST minimizes the total weight. The path between two vertices inside it can be much longer than their shortest path in the graph.
      • 
      
    • Maximum spanning trees work the same way: sort heaviest-first, or negate the weights.
      • 
      
    • Directed graphs need a different algorithm. The directed version, a minimum spanning arborescence, is solved by the Chu–Liu/Edmonds algorithm.
      • 
      
    • Uses beyond cables: clustering (build the MST, then delete its k − 1 heaviest edges to get k clusters), image segmentation, and a 2-approximation for the traveling salesperson problem when distances obey the triangle inequality.
      • 
    
    

    
    The code
    
    
    Both algorithms in Go. Kruskal uses union find with path compression; Prim uses container/heap and skips heap entries whose far end is already in the tree.
    

    import (
	"cmp"
	"container/heap"
	"slices"
)

// WEdge is an undirected edge with a weight.
type WEdge struct {
	U, V, Weight int
}

// Kruskal returns a minimum spanning tree (a forest, if the graph isn't
// connected) and its total weight. Vertices are 0..n-1.
func Kruskal(n int, edges []WEdge) ([]WEdge, int) {
	sorted := slices.Clone(edges)
	slices.SortFunc(sorted, func(a, b WEdge) int { return cmp.Compare(a.Weight, b.Weight) })

	parent := make([]int, n) // union find with path compression
	for i := range parent {
		parent[i] = i
	}
	var find func(int) int
	find = func(x int) int {
		if parent[x] != x {
			parent[x] = find(parent[x])
		}
		return parent[x]
	}

	var tree []WEdge
	total := 0
	for _, e := range sorted {
		ru, rv := find(e.U), find(e.V)
		if ru == rv {
			continue // already connected: this edge would close a cycle
		}
		parent[ru] = rv
		tree = append(tree, e)
		total += e.Weight
	}
	return tree, total
}

// Prim grows a minimum spanning tree outward from start, always adding the
// cheapest edge that leaves the tree. adj[v] lists v's edges (U is v).
func Prim(adj [][]WEdge, start int) ([]WEdge, int) {
	inTree := make([]bool, len(adj))
	inTree[start] = true
	h := &edgeHeap{}
	for _, e := range adj[start] {
		heap.Push(h, e)
	}
	var tree []WEdge
	total := 0
	for h.Len() > 0 {
		e := heap.Pop(h).(WEdge)
		if inTree[e.V] {
			continue // both ends already in the tree: skip
		}
		inTree[e.V] = true
		tree = append(tree, e)
		total += e.Weight
		for _, next := range adj[e.V] {
			if !inTree[next.V] {
				heap.Push(h, next)
			}
		}
	}
	return tree, total
}

// edgeHeap is a min-heap of edges by weight, for container/heap.
type edgeHeap []WEdge

func (h edgeHeap) Len() int           { return len(h) }
func (h edgeHeap) Less(i, j int) bool { return h[i].Weight < h[j].Weight }
func (h edgeHeap) Swap(i, j int)      { h[i], h[j] = h[j], h[i] }
func (h *edgeHeap) Push(x any)        { *h = append(*h, x.(WEdge)) }
func (h *edgeHeap) Pop() any {
	old := *h
	x := old[len(old)-1]
	*h = old[:len(old)-1]
	return x
}
    

    
    
      
    Interview notes
    
      
    How often it comes up: Moderate to low. Usually disguised as "connect everything at the minimum total cost."
    
      
    Be ready to:
    
      
    • Write Kruskal with union find from memory.
    • Sketch Prim with a priority queue, and know when the O(V²) version wins (dense or complete graphs).
    • Spot MST problems in disguise, like points on a plane, or adding a virtual vertex.
