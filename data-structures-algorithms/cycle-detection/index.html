Cycle detection

A cheat sheet. Does this graph contain a cycle? The right technique depends on whether edges have a direction, how the graph is given to you, and what else you need from the answer.

Which technique?

TechniqueGraphReach for it when…Cost
Union findundirectedEdges come as a list, or arrive one at a time; you want the first edge that closes a cycle~O(E)
DFS, skip the way backundirectedYou have an adjacency list, or want to find the cycle itselfO(V + E)
Count edgesundirectedYou only need yes or no, and know the number of componentsO(V + E)
Three-color DFSdirectedThe default for directed graphs; can also return the cycleO(V + E)
Kahn's algorithmdirectedYou also want a topological order, or need to avoid recursionO(V + E)
Strongly connected componentsdirectedYou need every group of vertices that lie on cycles togetherO(V + E)
Tortoise and hareone edge outEach vertex has at most one outgoing edge (linked lists, "next" arrays); O(1) extra spaceO(length)

The deep reason undirected and directed graphs need different tools: in an undirected graph, any edge between two vertices you can already reach from each other closes a cycle. In a directed graph, an edge to an already-visited vertex only closes a cycle if you can get from that vertex back to where you are.

Undirected graphs

Union find undirected

Process edges one by one. If an edge's two endpoints already have the same root, they're already connected, so this edge closes a cycle. Otherwise, union them.

Gives you
The first edge that closes a cycle, as edges arrive. Works without building an adjacency list.
Watch out
It tells you that a cycle exists, not which vertices are on it.
More
Union Find explainer
Go code
// CycleUnionFind reports whether an undirected graph has a cycle: an edge
// whose endpoints are already connected closes one.
func CycleUnionFind(n int, edges [][2]int) bool {
	parent := make([]int, n)
	for i := range parent {
		parent[i] = i
	}
	var find func(int) int
	find = func(x int) int {
		if parent[x] != x {
			parent[x] = find(parent[x])
		}
		return parent[x]
	}
	for _, e := range edges {
		a, b := find(e[0]), find(e[1])
		if a == b {
			return true
		}
		parent[a] = b
	}
	return false
}

DFS, skipping the edge you arrived on undirected

Run a DFS. Every edge you meet either leads to a new vertex or to one you've already visited. An edge to an already-visited vertex closes a cycle, except the edge you just arrived along, which would trivially lead back to your parent.

Gives you
The cycle itself, if you keep parent pointers: when you find the closing edge, walk parents from one end back to the other.
Watch out
Skip the arrival edge by its edge ID, not by "don't go back to the parent vertex". With two parallel edges between the same pair, that pair is a cycle, and the vertex check would miss it.
More
BFS and DFS, Which edges can you remove? (bridges are exactly the edges on no cycle)
Go code
// CycleUndirectedDFS does the same with a DFS. Any edge to an already
// visited vertex closes a cycle, except the edge we arrived on. Skipping it
// by edge ID (not by vertex) keeps duplicate edges counted as a cycle.
func CycleUndirectedDFS(n int, edges [][2]int) bool {
	type half struct{ to, id int }
	adj := make([][]half, n)
	for id, e := range edges {
		adj[e[0]] = append(adj[e[0]], half{e[1], id})
		adj[e[1]] = append(adj[e[1]], half{e[0], id})
	}
	visited := make([]bool, n)
	var visit func(v, cameFrom int) bool
	visit = func(v, cameFrom int) bool {
		visited[v] = true
		for _, h := range adj[v] {
			if h.id == cameFrom {
				continue
			}
			if visited[h.to] || visit(h.to, h.id) {
				return true
			}
		}
		return false
	}
	for v := 0; v < n; v++ {
		if !visited[v] && visit(v, -1) {
			return true
		}
	}
	return false
}

Just count undirected

A forest (a graph with no cycles) on V vertices with c connected components has exactly V − c edges. So an undirected graph has a cycle exactly when E > V − c. For a connected graph: a cycle exists exactly when E ≥ V.

Gives you
A yes or no with almost no code, once you know c (from any BFS, DFS, or union find).
Classic use
"Is this graph a tree?" means: connected and exactly V − 1 edges.

Directed graphs

Three-color DFS directed

Color every vertex white (unvisited), gray (on the current DFS path, still being explored) or black (finished). An edge to a gray vertex points back to an ancestor on the current path: that's a cycle. An edge to a black vertex is fine.

Gives you
Yes or no, or the cycle itself: when you hit a gray vertex, the cycle is the part of the current path from that vertex onward.
Watch out
Two colors (just "visited") are not enough. See the diagram below. Also loop over every vertex as a starting point, since one DFS only covers what it can reach.
More
Topological sort (the same DFS, collecting finish order)
Go code
// CycleDirected reports whether a directed graph has a cycle, with a
// three-color DFS. Only an edge to a gray vertex (one on the current path)
// closes a cycle; an edge to a black (finished) vertex doesn't.
func CycleDirected(n int, edges [][2]int) bool {
	adj := make([][]int, n)
	for _, e := range edges {
		adj[e[0]] = append(adj[e[0]], e[1])
	}
	const white, gray, black = 0, 1, 2
	color := make([]int, n)
	var visit func(v int) bool
	visit = func(v int) bool {
		color[v] = gray
		for _, w := range adj[v] {
			if color[w] == gray || (color[w] == white && visit(w)) {
				return true
			}
		}
		color[v] = black
		return false
	}
	for v := 0; v < n; v++ {
		if color[v] == white && visit(v) {
			return true
		}
	}
	return false
}

Kahn's algorithm directed

Repeatedly remove vertices with no incoming edges. If you remove all V of them, there's no cycle. If you get stuck with vertices left over, there is one: vertices on a cycle are each waiting on another vertex of the cycle, so they never become free.

Gives you
A topological order for free when there's no cycle. Iterative, so no recursion depth limits.
Watch out
The leftover vertices aren't all on a cycle. Some are only downstream of one. To report the cycle itself, use the three-color DFS.

Strongly connected components directed

Every directed cycle lies inside one strongly connected component, and every component with two or more vertices contains a cycle. So: the graph has a cycle exactly when some SCC has more than one vertex, or some vertex has an edge to itself.

Gives you
Every group of vertices that are on cycles together, in one pass, plus the condensed DAG of how the groups depend on each other.
Watch out
It's more machinery than a yes-or-no question needs. Self-loops don't make a bigger SCC, so check them separately.
More

Special case: one edge out per vertex

Floyd's tortoise and hare one edge out

When each vertex has at most one outgoing edge, following edges from a start traces a single path, which either ends or eventually loops. Move one pointer one step at a time and another two steps at a time. If there's a loop, the fast pointer laps the slow one and they meet; if not, the fast pointer reaches the end.

Gives you
A yes or no in O(1) extra space. With one more phase (reset one pointer to the start, then move both one step at a time) they meet at the first vertex of the loop.
Where it shows up
Linked lists, "next pointer" arrays, repeatedly applying a function (x → f(x)), and finding a duplicate in an array of values that index into the array.
Alternative
If extra space is fine, the three colors work too, and can label every vertex on every loop in one pass.
Go code
// CycleFromStart follows next pointers from start (next[v] == -1 means the
// chain ends) and reports whether it loops, using Floyd's tortoise and hare
// in O(1) extra space.
func CycleFromStart(next []int, start int) bool {
	slow, fast := start, start
	for fast != -1 && next[fast] != -1 {
		slow, fast = next[slow], next[next[fast]]
		if slow == fast {
			return true
		}
	}
	return false
}

Gotchas

  • Disconnected graphs. One search only covers what it can reach. Start a new search from every vertex not yet visited.
  • Self-loops and duplicate edges. An edge from a vertex to itself is a cycle of length 1. Two edges between the same pair of vertices form a cycle of length 2 in an undirected graph. All the code on this page counts both; check what your problem wants.
  • Undirected parent check by vertex vs. by edge. "Skip the parent vertex" misses duplicate edges. "Skip the edge I arrived on" handles them.
  • "Visited" isn't enough for directed graphs. Use three colors (or a separate "on the current path" set).
  • Recursion depth. On long paths, recursive DFS can overflow the stack. Kahn's algorithm, union find, and DFS with an explicit stack avoid it.
  • Finding vs. detecting. Most methods stop at "yes". To report the cycle, keep parent pointers (undirected DFS) or the current path (directed DFS), and read the cycle off when you find the closing edge.

Interview notes

How often it comes up: High, usually inside another problem: "can all courses be finished?", "is this a valid tree?", "does this linked list loop?"
