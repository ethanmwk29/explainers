Shortest paths

The cheapest route from one vertex to all the others, when edges have costs. Which algorithm you need depends almost entirely on what the weights look like.

The shared idea: relaxation

Every algorithm here keeps a tentative distance dist[v] for each vertex: the cheapest way to reach v found so far. It starts at 0 for the source and ∞ for everything else. The only operation is relaxing an edge u → v with weight w:

If dist[u] + w < dist[v], then going through u is a cheaper way to reach v: set dist[v] = dist[u] + w, and remember u as v's predecessor.

The algorithms differ only in which edges they relax, in what order. Following predecessors back from any vertex gives its actual cheapest path, and together they form a shortest-path tree.

  • Dijkstra is greedy. It repeatedly picks the unfinished vertex with the smallest tentative distance, declares that distance final, and relaxes its outgoing edges. This is correct because, with no negative edges, no later detour can ever come back cheaper: any other route has to pass through a vertex that's already at least as far away.
  • Bellman–Ford is patient. It relaxes every edge, over and over. A cheapest path never repeats a vertex, so it has at most V − 1 edges, and after pass k, every cheapest path of up to k edges has been found. So V − 1 passes are always enough. If a V-th pass still improves something, there's a negative cycle: a loop you could go around forever to make the cost lower and lower.

Why a negative edge breaks Dijkstra

    
Dijkstra's guarantee rests on one fact: once a vertex is the closest unfinished one, nothing found later can beat it, because every remaining route starts from a vertex that's at least as far away and can only get more expensive from there. A negative edge breaks that: a far-away vertex can have an edge that makes the total cheaper. In the example, C is finalized at 4 before F (at distance 6) is explored, and then F → C reveals a route to C costing 2. Dijkstra has already moved on, so C's improvement never reaches D, E and T.

    
(Some Dijkstra implementations re-add a vertex whenever its distance improves, even after it's been finished. With negative edges, that version gets the right answer when there's no negative cycle, but it loses its speed guarantee: in the worst case it takes exponential time. Use Bellman–Ford instead.)


    
Variations worth knowing

    
    
      
  • At most k edges. Run Bellman–Ford for exactly k passes, relaxing each pass from a copy of the previous pass's distances, so a single pass can't chain several edges together. That gives the cheapest path using at most k edges, a common interview twist ("cheapest flight with at most k stops").
    • 
      
  • Floyd–Warshall computes all pairs with three nested loops: for each vertex k, for every pair (i, j), try going through k. It handles negative edges, and a negative value on the diagonal means a negative cycle.
    • 
      
  • Other "costs". The same machinery works for other ways of combining a path's edges. Maximum probability (multiply, take the max), or minimum effort (the cost of a path is its largest edge) both run with a Dijkstra-style priority queue.
    • 
      
  • Undirected graphs are directed graphs with an edge in each direction. But a single negative undirected edge is already a negative cycle (go back and forth), so Bellman–Ford on undirected graphs only makes sense with non-negative weights.
    • 
    


    
The code

    
Dijkstra (with a min-heap and a "finished" set) and Bellman–Ford (with early stopping and negative-cycle detection) in Go. Both are tested against Floyd–Warshall on thousands of random graphs, including negative weights and negative cycles for Bellman–Ford.


import (
	"container/heap"
	"math"
)

// Arc is a directed, weighted edge.
type Arc struct{ From, To, Weight int }

// Inf marks a vertex that can't be reached.
const Inf = math.MaxInt

// Dijkstra returns the shortest distance from src to every vertex.
// Every weight must be non-negative.
func Dijkstra(n int, arcs []Arc, src int) []int {
	adj := make([][]Arc, n)
	for _, a := range arcs {
		adj[a.From] = append(adj[a.From], a)
	}
	dist := make([]int, n)
	for i := range dist {
		dist[i] = Inf
	}
	dist[src] = 0
	done := make([]bool, n)
	h := &minHeap{{src, 0}}
	for h.Len() > 0 {
		v := heap.Pop(h).(entry).v
		if done[v] {
			continue // an older, longer entry for a vertex we've already finished
		}
		done[v] = true // the closest unfinished vertex: its distance is final
		for _, a := range adj[v] {
			if d := dist[v] + a.Weight; d < dist[a.To] {
				dist[a.To] = d
				heap.Push(h, entry{a.To, d})
			}
		}
	}
	return dist
}

// BellmanFord allows negative weights. negCycle is true if a negative cycle
// can be reached from src, in which case some distances are meaningless.
func BellmanFord(n int, arcs []Arc, src int) (dist []int, negCycle bool) {
	dist = make([]int, n)
	for i := range dist {
		dist[i] = Inf
	}
	dist[src] = 0
	for pass := 1; pass < n; pass++ { // a shortest path has at most n-1 edges
		changed := false
		for _, a := range arcs {
			if dist[a.From] != Inf && dist[a.From]+a.Weight < dist[a.To] {
				dist[a.To] = dist[a.From] + a.Weight
				changed = true
			}
		}
		if !changed {
			return dist, false // nothing improved, so nothing ever will
		}
	}
	for _, a := range arcs { // one more pass: any improvement means a negative cycle
		if dist[a.From] != Inf && dist[a.From]+a.Weight < dist[a.To] {
			return dist, true
		}
	}
	return dist, false
}

type entry struct{ v, dist int }
type minHeap []entry

func (h minHeap) Len() int           { return len(h) }
func (h minHeap) Less(i, j int) bool { return h[i].dist < h[j].dist }
func (h minHeap) Swap(i, j int)      { h[i], h[j] = h[j], h[i] }
func (h *minHeap) Push(x any)        { *h = append(*h, x.(entry)) }
func (h *minHeap) Pop() any {
	old := *h
	x := old[len(old)-1]
	*h = old[:len(old)-1]
	return x
}


    

      
Interview notes

      
How often it comes up: High for Dijkstra, moderate for Bellman–Ford, low for Floyd–Warshall. The most common trap is using Dijkstra when BFS would do, or BFS when edges have weights.

      
Be ready to:

      
  • Write Dijkstra with a min-heap, including skipping stale heap entries.
  • Explain why Dijkstra needs non-negative weights, with a small counterexample.
  • Adapt Bellman–Ford to "at most k edges" by relaxing from a copy of the previous pass.
  • Recognize Dijkstra in disguise: when a path's cost is a max, a product, or a sum of grid values.
