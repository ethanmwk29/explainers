Which edges can you remove?

You have an undirected graph and want to delete edges without disconnecting it. That sounds like one question, but it's really two, and they have different answers.

1. One at a time

Which single edges can I remove and stay connected? The answer is every edge that isn't a bridge. It's unique, and one depth-first search finds all of them.

2. All at once

What's the largest set of edges I can remove together and stay connected? Everything outside a spanning tree: E − (V − 1) edges. Many different sets work.

A triangle shows why they differ. Remove any one of its three edges and it stays connected, so no edge is a bridge. But you can't remove all three: at most one can go at a time.

Bridges

A bridge (also called a cut edge) is an edge whose removal splits the graph into more pieces. Two equivalent ways to say it:

  • Removing it leaves its two endpoints with no other path between them.
  • It doesn't lie on any cycle. If an edge is on a cycle, the rest of the cycle is a detour around it.

A graph with no bridges at all is called 2-edge-connected: you have to cut at least two edges to disconnect it.

Finding every bridge in one search

The brute-force way is to remove each edge in turn and check whether the graph is still connected: one full search per edge, O(E · (V + E)). A single depth-first search can do the whole job in O(V + E), using the same index / low idea as Tarjan's SCC algorithm.

As the DFS runs, every edge becomes one of two kinds:

  • Tree edges lead to a vertex the search hasn't seen yet. Together they form a spanning tree (the DFS tree).
  • Non-tree edges lead to a vertex that's already been visited. In an undirected DFS, a non-tree edge always connects a vertex to one of its own ancestors in the tree.

That gives the two moments of decision:

  • A non-tree edge is safe the moment you see it. Its endpoints are already connected through tree edges, so it closes a cycle.
  • A tree edge u–v is decided when the search returns from v. By then low[v] holds the earliest index that anything in v's subtree can reach by one non-tree edge. If low[v] > index[u], nothing under v reaches back to u or above it, so u–v is the only way in: a bridge. Otherwise some non-tree edge loops around it, and it's safe.

Which edges become tree edges depends on where the search starts, so that part is arbitrary. Whether an edge is a bridge is not. Use the start-vertex menu below: the tree changes every time, but the bridges never do.

All at once: spanning trees

    
For the second question, you want to keep as few edges as possible while staying connected. A connected graph on V vertices needs at least V − 1 edges, and a spanning tree (a tree that touches every vertex) has exactly that many. So the most you can remove at once is E − (V − 1), or E − (V − c) if the graph starts with c separate pieces.

    
Finding one is easy: BFS, DFS, or union find all work in about O(V + E). With union find, walk the edges and keep each one only if union(u, v) actually merges two groups. Every rejected edge closes a cycle and can go.


    
How the two answers fit together

    
    
      
  • Every bridge is in every spanning tree. You can't stay connected without it.

  • So every spanning tree is all the bridges, plus enough edges chosen from the cycles to connect everything else. The bridges are forced; the cycle edges are the choices. That's why the maximum set isn't unique: try Show a maximum set a few times in the playground.

  • The bridges are a subset of every spanning tree, and a strict subset exactly when the graph has a cycle. If the graph is itself a tree, every edge is a bridge.

The vertex version: articulation points

    
The same DFS also finds articulation points (cut vertices): vertices whose removal disconnects the graph. When the search returns from child v to u, check low[v] ≥ index[u] instead of >. If nothing under v reaches above u, then u is the only link to v's subtree. The root of the DFS is a special case: it's an articulation point exactly when it has two or more tree children.


    
What changes for directed graphs

    
For directed graphs the natural goal is to keep the graph strongly connected (or keep its SCCs intact). The one-at-a-time question stays easy, but the all-at-once question becomes very hard:

    

      
One at a timeAll at once

      
        
Undirected (or weakly connected)Bridges: one DFS, O(V + E)Remove everything outside a spanning tree, O(V + E)

        
Strongly connectedStrong bridges: O(V + E) using dominator trees of the graph and its reverse (Italiano, Laura & Santaroni, 2012)NP-hard: keeping just V edges is possible only if the graph has a Hamiltonian cycle

      
    

    
The DFS shortcut also mostly disappears. In an undirected DFS, every non-tree edge is safe on sight because the tree path works in both directions. In a directed DFS, the tree path only goes one way, so only forward edges (to an already-finished descendant) are safe on sight. Back edges and cross edges might be the only way back. In the cycle A → B → C → A, the back edge C → A is essential. To keep SCCs intact you first need the SCCs themselves (from Tarjan or Kosaraju). After that, edges between SCCs can always go, and edges inside each SCC are checked for strong bridges.


    
The code

    
Bridge finding in Go. Edges carry IDs, so the "skip the edge we came in on" rule stays correct even with duplicate edges between the same two vertices.


// Edge is an undirected edge between vertices U and V.
type Edge struct{ U, V int }

// Bridges returns the positions (in edges) of every bridge in an undirected
// graph with vertices 0..n-1. Duplicate edges are handled correctly.
func Bridges(n int, edges []Edge) []int {
	type half struct{ to, id int }
	adj := make([][]half, n)
	for id, e := range edges {
		adj[e.U] = append(adj[e.U], half{e.V, id})
		adj[e.V] = append(adj[e.V], half{e.U, id})
	}
	index := make([]int, n)
	low := make([]int, n)
	for i := range index {
		index[i] = -1 // -1 means "not visited yet"
	}
	counter := 0
	var bridges []int

	var dfs func(u, cameFrom int)
	dfs = func(u, cameFrom int) {
		index[u], low[u] = counter, counter
		counter++
		for _, h := range adj[u] {
			if h.id == cameFrom {
				continue // don't walk straight back along the edge we arrived on
			}
			if index[h.to] == -1 { // tree edge: explore, then decide
				dfs(h.to, h.id)
				low[u] = min(low[u], low[h.to])
				if low[h.to] > index[u] {
					bridges = append(bridges, h.id) // nothing below reaches u or above
				}
			} else { // non-tree edge: it closes a cycle, so it's never a bridge
				low[u] = min(low[u], index[h.to])
			}
		}
	}

	for v := 0; v < n; v++ {
		if index[v] == -1 {
			dfs(v, -1)
		}
	}
	return bridges
}
