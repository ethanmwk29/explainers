Tarjan's strongly connected components algorithm

One depth-first search, two numbers per vertex, and a stack are enough to split any directed graph into the groups of vertices that can all reach each other.

What's a strongly connected component?

In a directed graph, edges are one-way streets. Two vertices are strongly connected if you can get from each one to the other by following edges forward. A strongly connected component (SCC) is a maximal group in which every vertex can reach every other.

Every vertex belongs to exactly one SCC. Finding them is useful whenever cycles matter: spotting circular dependencies between modules or packages, finding deadlocks, solving 2-SAT problems, and simplifying a graph by collapsing each component into a single node.

The three ideas

Tarjan's algorithm does one depth-first search (DFS) and keeps three pieces of bookkeeping:

  • index[v]: the order in which the DFS first visits v (0, 1, 2, …).
  • low[v] (the "low-link"): the smallest index that v is known to reach by going down its part of the DFS and then taking at most one edge back to a vertex that's still on the stack. If low[v] is smaller than index[v], then v can get back to something visited before it, so it's part of an earlier vertex's component.
  • A stack of vertices that have been visited but not yet assigned to a component. Each vertex is pushed when it's first visited and stays on the stack until its whole component is complete, even after the DFS has finished with it.

The key moment comes when the DFS finishes a vertex v and finds low[v] == index[v]. Nothing reachable from v leads back to anything earlier, so v is the first-visited vertex, the root, of its component. Everything above v on the stack is in its component, so the algorithm pops them all off as one SCC.

      Why the "on the stack" check matters
      
    
      When the DFS meets an edge v → w to an already-visited vertex, there are two very different cases:
      
    
        
      
      • w is still on the stack. Its component isn't finished, and since w was visited earlier in the current search, w can reach v. Now v can reach w too, so they're in the same component. Update low[v].
        • 
      
      • w is off the stack. Its component is already finished. If w could reach v, they'd have been grouped together, so this edge leads into a different component, and the algorithm ignores it. In the first example graph, the edges B → D and I → H are like this.
        • 
    
      

    
      A bonus: the order components come out in
      
    
      A component is only completed after every component it can reach is finished. So Tarjan's algorithm emits SCCs in reverse topological order: if you collapse each component into a single node, you get a DAG, and the list of components read backwards is a valid order to process it. Dependency resolvers use this directly. Build each component only after everything it depends on.
      

    
      How fast is it?
      
    
      Every vertex is visited once and every edge is looked at once, so the algorithm runs in O(V + E) time, the same as a single DFS. The stack and the two arrays take O(V) extra space.
      
    
      The other well-known SCC algorithm, Kosaraju's, is also O(V + E) but needs two full passes: one DFS on the graph, then another on the graph with every edge reversed. Tarjan's does it in a single pass and never builds the reversed graph.
      

    
      The code
      

      // TarjanSCC returns the strongly connected components of a graph with
// vertices 0..n-1, where graph[v] lists the vertices that v has edges to.
func TarjanSCC(graph [][]int) [][]int {
	n := len(graph)
	index := make([]int, n)
	low := make([]int, n)
	onStack := make([]bool, n)
	for i := range index {
		index[i] = -1 // -1 means "no index yet"
	}
	var stack []int
	var sccs [][]int
	counter := 0

	var strongconnect func(v int)
	strongconnect = func(v int) {
		index[v], low[v] = counter, counter
		counter++
		stack = append(stack, v)
		onStack[v] = true

		for _, w := range graph[v] {
			if index[w] == -1 { // unvisited: recurse
				strongconnect(w)
				low[v] = min(low[v], low[w])
			} else if onStack[w] { // on the stack: same SCC
				low[v] = min(low[v], index[w])
			} // else: w is in a finished SCC, ignore
		}

		if low[v] == index[v] { // v is the root of an SCC
			var scc []int
			for {
				w := stack[len(stack)-1]
				stack = stack[:len(stack)-1]
				onStack[w] = false
				scc = append(scc, w)
				if w == v {
					break
				}
			}
			sccs = append(sccs, scc)
		}
	}

	for v := range graph {
		if index[v] == -1 {
			strongconnect(v)
		}
	}
	return sccs // in reverse topological order
}
      

    
      Caveats
      
    
        
      
      • Recursion depth. On a graph with a very long path, the recursive version can overflow the call stack. Large-scale implementations use an explicit stack of (vertex, next-edge) pairs instead.
        • 
      
      • Two ways to update low. For an edge to a vertex on the stack, some versions use low[w] instead of index[w]. Both find the same components. index[w] matches Tarjan's original paper and makes low easier to reason about.
        • 
      
      • Use a set for the on-stack check. Scanning the stack for w would cost O(V) per edge. Keep a boolean slice (like onStack in the Go code above) so the check takes O(1).
